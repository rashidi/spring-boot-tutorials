Large Language Models (LLMs) are stateless by design: each inference call executes independently without retaining memory of previous interactions. To deliver coherent conversational experiences, earlier dialogue turns must be appended to the prompt context window.

In this tutorial, we will explore how to implement durable conversational state management in https://spring.io/projects/spring-ai[Spring AI] using `JdbcChatMemory` backed by PostgreSQL, and verify message persistence across turns with https://testcontainers.com/[Testcontainers].

== Why Durable Chat Memory?

While in-memory chat storage works for single-instance prototyping, production cloud deployments require:

* *Resilience*: Preserve conversation context across application restarts and rolling deployments.
* *Horizontal Scalability*: Allow multiple service instances behind a load balancer to access identical conversation threads.
* *Session Isolation*: Partition message history reliably by `conversationId`.

val springAiVersion = "2.0.2"

dependencies {

== ChatClient Configuration

In link:{source-main}/ChatClientConfiguration.java[`ChatClientConfiguration`], we register `JdbcChatMemory` and attach `MessageChatMemoryAdvisor`:

[source,java]
----
@Configuration(proxyBeanMethods = false)
class ChatClientConfiguration {

    @Bean
    ChatMemory chatMemory(JdbcTemplate jdbcTemplate) {
        return JdbcChatMemory.create(JdbcChatMemoryConfig.builder()
                .withJdbcTemplate(jdbcTemplate)
                .build());
    }

    @Bean
    ChatClient chatClient(ChatClient.Builder builder, ChatMemory chatMemory) {
        return builder
                .defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
                .build();
    }

}
----

== Conversational Assistant Service

link:{source-main}/CustomerSupportAssistant.java[`CustomerSupportAssistant`] uses `ChatClient` with a caller-provided `conversationId`:

[source,java]
----
@Service
public class CustomerSupportAssistant {

    private final ChatClient chatClient;

    public CustomerSupportAssistant(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    public String chat(String conversationId, String userMessage) {
        return chatClient.prompt()
                .user(userMessage)
                .advisors(advisor -> advisor.param(AbstractChatMemoryAdvisor.CHAT_MEMORY_CONVERSATION_ID_KEY, conversationId))
                .call()
                .content();
    }

}
----

== Integration Testing with Testcontainers

We verify conversation persistence across multiple turns against an actual PostgreSQL container.

@TestConfiguration(proxyBeanMethods = false)
public class TestcontainersConfiguration {

    @Bean

=== Multi-Turn Verification Test

In link:{source-test}/CustomerSupportAssistantIntegrationTests.java[`CustomerSupportAssistantIntegrationTests`], we simulate a multi-turn conversation and assert history persistence:

[source,java]
----
@SpringBootTest
@Import(TestcontainersConfiguration.class)
class CustomerSupportAssistantIntegrationTests {

    @Autowired
    private CustomerSupportAssistant assistant;

    @Autowired
    private ChatMemory chatMemory;

    @Test
    @DisplayName("When chatting across multiple turns Then conversation history is persisted and isolated")
    void maintainsConversationHistory() {
        var conversationId = UUID.randomUUID().toString();

        assistant.chat(conversationId, "My order number is ORD-9921");
        assistant.chat(conversationId, "Can you confirm my order status?");

        var history = chatMemory.get(conversationId, 10);
        assertThat(history).hasSize(4); // 2 user turns + 2 assistant responses

        var isolatedConversationId = UUID.randomUUID().toString();
        var isolatedHistory = chatMemory.get(isolatedConversationId, 10);
        assertThat(isolatedHistory).isEmpty();
    }

}
----

Combining `JdbcChatMemory` with Spring AI's advisor architecture enables applications to persist conversational context reliably in PostgreSQL, validated against real containerized infrastructure with Testcontainers.
