In a modular monolith architecture, domain modules communicate in-process via strongly typed domain events. However, external distributed microservices or analytics platforms often require access to these lifecycle changes.

In this tutorial, we explore how to project internal domain events onto Apache Kafka topics using https://spring.io/projects/spring-modulith[Spring Modulith] event externalization (`@Externalized`), adhering to package-private encapsulation and verifying message delivery with https://testcontainers.com/[Testcontainers].

== Architecture & Modular Encapsulation

Following modular monolith principles, the application organizes code by business domain rather than technical layers:

* `zin.rashidi.boot.modulith.externalization.order`: Manages order lifecycles and emits domain events. Internal entities (`Order`) and repositories (`OrderRepository`) remain `package-private`, while `OrderService`, `OrderDto`, and `OrderCompletedEvent` form the public API boundary.
* `zin.rashidi.boot.modulith.externalization.shipping`: Consumes externalized events from the `orders.completed` Kafka topic via a `package-private` `ShippingKafkaListener` and exposes `ShippingTracker`.

== Externalized Event Contract

We define the public domain event in link:{source-main}/order/OrderCompletedEvent.java[`OrderCompletedEvent`] using `@Externalized` with a SpEL routing expression (`topic::#{#this.orderId()}`):

[source,java]
----
@Externalized("orders.completed::#{#this.orderId()}")
public record OrderCompletedEvent(
        Long orderId,
        String customerEmail,
        BigDecimal totalAmount,
        Instant timestamp
) {
}
----

== Domain Order Service

In link:{source-main}/order/OrderService.java[`OrderService`], the public facade manages state transitions and publishes the event within a `@Transactional` boundary:

[source,java]
----
@Service
public class OrderService {

    private final OrderRepository repository;
    private final ApplicationEventPublisher events;

    OrderService(OrderRepository repository, ApplicationEventPublisher events) {
        this.repository = repository;
        this.events = events;
    }

    @Transactional
    public OrderDto completeOrder(Long orderId) {
        var order = repository.findById(orderId)
                .orElseThrow(() -> new IllegalArgumentException("Order not found: " + orderId));

        order.setStatus(Order.OrderStatus.COMPLETED);
        var saved = repository.save(order);

        events.publishEvent(new OrderCompletedEvent(
                saved.getId(),
                saved.getCustomerEmail(),
                saved.getTotalAmount(),
                Instant.now()
        ));

        return new OrderDto(saved.getId(), saved.getCustomerEmail(), saved.getTotalAmount(), saved.getStatus().name());
    }

}

== Integration Testing with Testcontainers

We verify both module architecture rules and Kafka externalization using Testcontainers in link:{source-test}/TestcontainersConfiguration.java[`TestcontainersConfiguration`]:

[source,java]
----
@TestConfiguration(proxyBeanMethods = false)
public class TestcontainersConfiguration {

    @Bean
    @ServiceConnection
    PostgreSQLContainer<?> postgresContainer() {
        return new PostgreSQLContainer<>(DockerImageName.parse("postgres:latest"))
                .withInitScripts("schema.sql");
    }

    @Bean
    @ServiceConnection
    KafkaContainer kafkaContainer() {
        return new KafkaContainer(DockerImageName.parse("apache/kafka-native:latest"));
    }

}
----

In link:{source-test}/order/OrderExternalizationIntegrationTests.java[`OrderExternalizationIntegrationTests`], we verify that completing an order persists the event publication and externalizes the payload to the `orders.completed` Kafka topic:

[source,java]
----
@Import(TestcontainersConfiguration.class)
@SpringBootTest
@DisplayName("Given an order lifecycle, When an order is completed, Then the domain event is externalized to Kafka")
class OrderExternalizationIntegrationTests {

    @Autowired
    private OrderService orderService;

    @Autowired
    private ShippingTracker shippingTracker;

    @Autowired
    private EventPublicationRepository publicationRepository;

    @Test
    @DisplayName("Given a created order, When completeOrder is invoked, Then OrderCompletedEvent is published to the orders.completed Kafka topic")
    void orderCompletedEventIsExternalizedToKafka() {
        var created = orderService.createOrder("rashidi@zin.my", BigDecimal.valueOf(149.50));

        var completed = orderService.completeOrder(created.id());

        assertThat(completed.status()).isEqualTo("COMPLETED");

        await().atMost(Duration.ofSeconds(10)).untilAsserted(() -> {
            assertThat(shippingTracker.getCompletedOrders())
                    .hasSize(1)
                    .first()
                    .satisfies(event -> {
                        assertThat(event.orderId()).isEqualTo(created.id());
                        assertThat(event.customerEmail()).isEqualTo("rashidi@zin.my");
                        assertThat(event.totalAmount()).isEqualByComparingTo(BigDecimal.valueOf(149.50));
                    });

            assertThat(publicationRepository.findIncompletePublications()).isEmpty();
        });
    }

}
