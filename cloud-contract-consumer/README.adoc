The `cloud-contract-consumer` submodule demonstrates how to implement a consumer in Consumer-Driven Contracts using Spring Cloud Contract Stub Runner.

== Overview

When integrating with external APIs in a distributed architecture, we need a reliable way to verify that our HTTP clients are communicating correctly with the producer service. By using Spring Cloud Contract Stub Runner, we can run a mocked server using the actual stubs provided and generated by the producer.

== Implementation

This consumer application uses `RestClient` to interact with the producer API to retrieve `Book` records.

=== Consumer Client

The `BookClient` class makes an HTTP GET request to fetch a specific book using its ID.

[source,java]
----
@Service
class BookClient {
    private final RestClient restClient;

    public Book getBook(String baseUrl, UUID id) {
        return restClient.get()
                .uri(baseUrl + "/books/{id}", id)
                .retrieve()
                .body(Book.class);
    }
}
----

=== Integration Testing with Stub Runner

We use `@AutoConfigureStubRunner` to automatically download the producer's stubs from our local Maven repository (`~/.m2`) and start a WireMock server on port `8080`.

[source,java]
----
@SpringBootTest
@AutoConfigureStubRunner(ids = "zin.rashidi.boot:cloud-contract-producer:+:stubs:8080", stubsMode = StubRunnerProperties.StubsMode.LOCAL)
class ConsumerApplicationTests {

    @Autowired
    private BookClient bookClient;

    @Test
    void shouldReturnBook() {
        // Test logic...
    }
}
----

== Running Tests

Before running the consumer tests, ensure that you have built the producer and published its stubs to the local Maven repository:

[source,bash]
----
./gradlew :cloud-contract-producer:publishToMavenLocal
----

Then, execute the consumer tests:

[source,bash]
----
./gradlew :cloud-contract-consumer:test
----
